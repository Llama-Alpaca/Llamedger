## 方向变更记录

- 2026-08-29：最初理解为 Windows 桌面软件（Python + PySide6），已废弃。
- 2026-09-13：确认为 **Android 手机 App**。取数通道确认为 **招商银行 App 推送通知为主力**，不是短信。

## 技术路线（已确认）

- 原生 Android View 手写界面，不用 Compose / AndroidX
- 不用 Gradle，直接用 SDK 原生工具链构建（本机没有 Android Studio）
- 业务核心 `core/` 保持纯 Java，可脱离手机在电脑上跑测试
- SQLite 本地存储，App 不联网

## 用户已知反馈

- 2026-09-13：微信零钱提现 3000 元到招行卡
  - 现象 1：招行推送「收款人民币3000.00元」完全没被识别 → 词典缺「收款」，已修
  - 现象 2：微信那条被记成 2 元支出 → 正则从「支付」跨到「预计2小时内到账」的 2，已修
  - 现象 3：提现本质是账户间转账，不该算支出/收入 → 新增内部转账引擎，已修
  - 追加：微信通知原文为「[2条]微信支付: 零钱提现已到账」，确认
    (a) 「2」来自「[2条]」通知分组计数，不是「2小时」
    (b) 该通知完全没有金额，无法靠它配对 → 新增「转账线索」机制，
        由银行入账侧依据 ±2 小时内的提现线索判定为转账

## 用户已知反馈

- 2026-09-16（第 5 轮）：**消费完全没有记录**
  - 用户提供的招行模板：您账户8888于09月16日10:50在【XXXX】发生快捷支付扣款，人民币xxxx
  - 根因（两处）：
    1. **包名白名单是精确匹配**。`NotifyListenerService.isWatched()` 里硬编码了一份包名列表，
       招行 App 只要换过包名就直接被静默丢弃，且不写任何日志 —— 表现为「一笔都没有」。
    2. 商户正则用「在…支付」截取，遇到「在【星巴克】发生快捷支付扣款」会把
       「发生快捷」一起吞进商户名。
  - 修复：
    1. 包名三级判断：精确名单 → 模糊特征片段（cmb/bank/icbc…）→ 文本兜底
       （金额 + 银行特征词 + 交易行为词 同时满足）
    2. 商户提取优先取括号里的名字，并加了噪音词截断
    3. 新增 `notify_src` 表（v4）：记录**所有**通知的包名与标题（不存正文），
       即使被过滤也能在「识别诊断」里看到它来过
    4. 新增「识别诊断」界面：通知使用权 / 监听连接 / 总开关 / 后台常驻 逐项体检
  - 新增 6 个回归用例，核心测试增至 26 项

## 常见问题排查

- 收不到推送 → 检查「通知使用权」是否开启、「电池优化白名单」是否加入
- 识别不出金额 → 把该条通知的完整文案发来，补解析规则
- 退款没自动冲销 → 说明缺佐证（商户/时间对不上），这是防误删设计；可在设置里调低匹配阈值
